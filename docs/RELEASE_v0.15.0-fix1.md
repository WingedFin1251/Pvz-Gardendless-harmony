本次是 **0.15.0 的修正版（fix1）**：把"闲置一会儿刷新率掉到 60Hz"按住，并给壳层加了一个设置面板。

## 1. 新增：壳层设置面板（长按 GP 按钮打开）

**怎么打开**：先点一下右下角的 **GP 按钮**把它唤出来（它闲置几秒后会贴边半隐），**再长按一下它** → 就会弹出设置面板。

面板里可以设置：

- **画面**：铺满 / 按比例留边（原先"长按 GP 按钮"的功能挪进了面板）
- **期望刷新率**：关闭 / 60 / 120 / 最高 —— 选完**立即生效**，并记住到下次启动
- 面板里还只读显示**当前屏幕刷新率**与屏幕支持的档位（面板打开期间每秒刷新）

> 这一项是向鸿蒙的**控帧系统**声明"本页面期望的帧率"。系统在无触摸、内容静止时会自适应降到 60Hz（对应官方 OpenGTX 的 `TOUCH_MODE` 语义），本项用于缓解该现象。
> 游戏**引擎自身**的帧率仍由 **GP-Next 面板 → 设置 → 帧率** 决定（默认 60，建议改成 120 或 不限）。两个开关相互独立，都设对才能长期 >60fps。

## 2. 期望刷新率投票（displaySync）

壳层用 `displaySync.setExpectedFrameRateRange()` 参与整机刷新率决策，且**只在页面可见时**持有（切后台即释放，避免空刷帧）。

实测（平板，全程零输入，唯一变量=该投票）：

| 条件 | 90 秒内的显示刷新率 |
| :--- | :--- |
| 投票关闭 | 60Hz × 18（120 占比 0%） |
| 投票开启 | 120Hz × 18（120 占比 100%） |

## 3. gpnext：负载更新到新版 GP-Next

- 游戏资源（`assets/main`、`assets/internal`、`assets/resources/**`）**逐字节一致**，仅前端 bundle 更新（新增 76 / 移除 57 个 chunk，`index.html` 同步更新）
- 上游新增 `frame-settings` 模块（走 Cocos `_pacer` / `setFrameRate`，属于**引擎帧率**那一层）

## 已知限制

- **通用（base）变体没有悬浮 GP 按钮**，因此它没有上述设置面板，只有内置的期望刷新率投票
- 面板里的「最高」按屏幕支持上限投票；本次仅实测了 60 / 120 两档
- 壳层仍未实现流式 `fs`（`open/read/write/seek/fstat/ftruncate`）与 `dialog|open`；目前负载未触发到
