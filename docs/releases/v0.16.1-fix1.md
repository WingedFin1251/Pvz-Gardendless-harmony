# Gardendless 鸿蒙版 v0.16.1(fix1)（GP-Next）

修复 **0.16.1 里"新版模组管理"无法导入** 的问题。负载内容与 v0.16.1 完全相同，只改了壳层。

## 问题现象

0.16.1 把 GP-Next 升到 1.5.5 后，模组页换成了新的管理方式（`导入 ZIP` / `导入文件夹`）。
点这两个按钮**没有任何反应**（旧版靠"打开数据包目录"的导入方式也因此失效）。

## 原因

新版模组导入改用 Tauri 的**文件选择**命令 `plugin:dialog|open` 拿用户选中的文件，
再用普通的 `lstat` / `read_dir` / `read_file` 去读它。鸿蒙壳层之前**只实现了 `dialog|save`（另存为）**，
没有 `dialog|open`，于是这条命令直接报"未兼容的 GP-Next 命令"，导入流程在第一步就断了。

另外移动端有个额外约束：原生文件系统只能访问应用沙箱（路径校验会拒绝沙箱外路径），
所以即使拿到了用户选择的 URI，也不能直接把它交给负载。

## 修复

- 新增 `plugin:dialog|open`：调系统文件选择器（按负载给的 `filters` 过滤后缀，例如只显示 `.zip`），
  然后把用户选中的文件**拷进沙箱的 `gp-next/.incoming/`**，返回**沙箱内的真实路径**给负载。
  负载随后用普通的 `lstat` / `read_dir` / `read_file` 读它，包内 ZIP 由负载自己的 inflate 解析，
  壳层不需要解压、也不需要理解模组格式。
- 多选（`multiple`）与取消都按 Tauri 语义返回（数组 / 路径字符串 / `null`）。
- 「导入文件夹」（`directory: true`）在鸿蒙的文档选择器里没有对应能力：**返回取消**而不是报错，
  并在日志里提示改用 ZIP 导入（不会让面板卡住）。

## 实测（平板）

- 点「导入 ZIP」→ **系统选择器正常弹出，且只列出 `.zip`** ✓
- 选中一个真实模组包 → 壳层日志 `已接收用户选择: …/.incoming/…zip`，沙箱内文件 **671,751 B** 与源文件一致 ✓
- 面板随即显示该模组的解析结果（名称 / 版本 / "包含 JavaScript" 提示 / `JS Modding 可用`），
  并给出 **安装 / 取消** 按钮 ✓ —— 是否安装仍由用户自己决定。
