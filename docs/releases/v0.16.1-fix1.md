# Gardendless 鸿蒙版 v0.16.1(fix1)（GP-Next）

修复 **0.16.1 里"新版模组管理"用不了**的问题：`导入 ZIP` / `导入文件夹` 点了没反应，`打开目录` 也不再打开目录。
负载内容与 v0.16.1 完全相同，只改壳层。

## 问题现象

0.16.1 把 GP-Next 升到 1.5.5 后，模组页换成了新的管理方式：

| 按钮 | 桌面版行为 | 0.16.1 鸿蒙版的问题 |
| :--- | :--- | :--- |
| `打开目录` | 打开 `gp-next` 文件夹 | 变成了弹"导入文件"选择器（旧逻辑） |
| `导入 ZIP` | 文件选择器选 `.zip` | **点了没反应** |
| `导入文件夹` | 选择器选一个文件夹 | **点了没反应** |

## 原因

新版导入先调 Tauri 的 `plugin:dialog|open` 拿用户选中的文件/文件夹，再用普通的
`lstat` / `read_dir` / `read_file` 去读它。鸿蒙壳层之前只实现了 `dialog|save`（另存为），
**没有 `dialog|open`** ⇒ 命令直接报"未兼容的 GP-Next 命令"，流程在第一步就断了。

另外移动端还有两个约束：

1. 原生文件系统只能访问应用沙箱（路径校验会拒绝沙箱外路径）⇒ 拿到 URI 后必须**先拷进沙箱**；
2. 系统"选文件夹"返回的是**目录 URI**，整目录复制要用对 API（见下）。

## 修复

- ⭐ **新增 `plugin:dialog|open`**：按负载给的 `filters` 过滤后缀（例如只显示 `.zip`）打开系统选择器，
  把用户选中的文件拷进沙箱的 `gp-next/.incoming/`，返回**沙箱内真实路径**给负载；
  多选按数组返回、取消返回 `null`。包内 ZIP 由负载自己的 inflate 解析，壳层不需要理解模组格式。
- ⭐ **`导入文件夹`**：用系统选择器的 **FOLDER 模式**选目录，再把整个目录复制进 `.incoming/`，
  返回落地路径。这里踩了两个 API 坑，都写进了代码注释：
  - `fs.copyFileSync(目录 uri, 沙箱路径)` ⇒ `13900002 No such file or directory`（它的**目标也必须是 URI**）；
  - `fs.copy(目录 uri, 尚不存在的目标 uri)` ⇒ `13900020 Invalid argument`
    （目标 URI 必须指向**已存在**的目录，让系统把源目录"复制进去"）。
- ⭐ **`打开目录`**：鸿蒙的应用沙箱是私有的，系统文件管理器进不来，所以改成在顶部提示条
  列出 `gp-next` 的目录内容（各子目录项数 + 顶层文件大小）。
- 系统选择器调用统一加 **180 秒超时**：选择器异常退出时 `select()` 可能永不返回，
  超时按"未选择"处理，避免调用方一直卡着。

## 实测（平板）

| 场景 | 结果 |
| :--- | :--- |
| `导入 ZIP` | 系统选择器弹出且**只列 `.zip`**；选中真实模组包后 `.incoming/` 落地 671,751 B（与源文件一致），面板显示模组名/版本与"安装/取消" ✓ |
| `导入文件夹` | 选择器可选出文件夹；`.incoming/` 下出现**同名目录**，负载解析后写入 `installed/<digest>`，面板可安装 ✓ |
| `打开目录` | 顶部提示条列出 `packs/ · 3 项 / patches/ · 0 项 / .incoming/ · 2 项 / installed/ · 2 项 …` ✓ |

## 已知限制

- ⚠️ `plugin:fs|open/read/seek/write/fstat/ftruncate`（底层 fd 流式接口）仍未实现。
  当前模组流程**不调用**这些命令（zip 由负载在 JS 里解析），因此不影响导入；
  将来若有功能用到，会以同样的"未兼容命令"错误暴露出来。
- ⚠️ 导入时复制到 `.incoming/` 的副本不会自动清理（目录导入会复用同名目录，不会无限增长）。
